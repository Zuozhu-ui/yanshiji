## 1. 产品定位与原则

**一句话**：一个纯本地的学习记录工具——把每天的学习时间记下来，并用统计和复盘让它变得看得见。

**目标用户**：考研 / 考公 / 考证 / 语言学习 / 大学课程等，需要长期记录学习投入并复盘的人。

**三条产品原则**

1. **纯本地**：不联网、不登录、不上传。所有数据只在本机，卸载即清空。
2. **低摩擦**：从打开到开始计时尽量少点击；忘记计时也能快速补录。
3. **看见积累**：今日、本周、连续天数、科目分布，让人有持续的动力。

**明确不做**：云同步 / 账号体系、社交与排行榜、任务管理与笔记系统。这些会把「安静的记录工具」变成别的东西，也与纯本地定位冲突。

## 2. 技术架构

### 2.1 分层

| 层 | 位置 | 职责 |
|---|---|---|
| 页面 | `src/pages/` | 首页、计时、统计、日志 |
| 组件 | `src/components/` | 卡片、图表、各类弹窗、底部导航 |
| 应用状态 | `src/App.jsx` | 持有 `config` / `records` / `timerState`，通过 props 下发 |
| 服务 | `src/services/` | 存储、计时状态机、自动备份、SAF 封装、金句 |
| 原生 | `android/app/src/main/java/com/yanshiji/app/` | `BackupFilePlugin`（系统文件选择器） |
| 设计 | `src/styles/tokens.css` | 设计令牌（颜色/字体/圆角/阴影） |

**没有引入路由库和状态库**。页面切换是 `App` 里的 `activeTab`；计时器是模块级单例 `timerService`，通过订阅通知 React。这个规模下足够，也避免了额外依赖。

### 2.2 数据流

```
用户操作
  → App handler（addRecord / updateRecord / deleteRecord / saveAppConfig）
  → storage 写 localStorage
  → setRecords / setConfig 触发重渲染
  → 6 秒后 autoBackup.saveSnapshot() 生成一份自动备份（原生端）
```

计时器是独立闭环：`TimerPage` 调 `timerService`，服务内部用 1s tick 刷新、10s 写心跳，React 只订阅状态。

## 3. 数据模型

### 3.1 localStorage 键（**不可修改**）

| key | 内容 |
|---|---|
| `yanshiji_study_records_v1` | 全部学习记录（数组） |
| `yanshiji_app_config_v1` | 目标日、日目标、主题、科目 |
| `yanshiji_daily_reflections_v1` | 按日期存的学习复盘 |
| `yanshiji_timer_heartbeat_v1` | 计时心跳（未结束时存在） |

> key 保持 `yanshiji_*` 是为了覆盖安装后能直接读到旧数据。改名不等于改 key。

### 3.2 学习记录 `study_record`

| 字段 | 类型 | 说明 |
|---|---|---|
| `record_id` | number | 自增主键（跨设备可能冲突，导入时会重排） |
| `start_timestamp` | number | 开始时间戳；补录时用「现在 − 时长」推导 |
| `end_timestamp` | number | 结束时间戳 |
| `duration_min` | number | 分钟，`ceil` 取整 |
| `subject_name` | string | 科目名 |
| `study_content` | string | 学习内容 |
| `record_date` | string | `yyyy-MM-dd`，统计与分组依据；计时记录取**开始日** |
| `created_at` | number | 录入时间（排序用） |
| `updated_at` | number | 最后修改时间 |

### 3.3 配置 `app_config`

| 字段 | 默认 | 说明 |
|---|---|---|
| `exam_target_date` | `''` | 目标日，空表示未设置（字段名保留兼容，不再限定考试） |
| `daily_target_min` | `300` | 每日目标分钟，0 表示关闭 |
| `theme_mode` | `light` | `light` / `dark` |
| `subjects` | 阅读/写作/练习/复习/其他 | `[{ name, color }]` |
| `schema_version` | `2` | 预留，当前不做逐级迁移 |

### 3.4 复盘 `reflections`

```json
{ "2026-10-23": { "content": "今天状态不错", "updated_at": 1792700000000 } }
```

### 3.5 备份格式（formatVersion 2）

```json
{
  "app": "学时记",
  "formatVersion": 2,
  "exportedAt": "2026-10-23T02:00:00.000Z",
  "config": { "examTargetDate": "2026-12-20", "dailyTargetMin": 300, "subjects": [] },
  "records": [
    {
      "recordId": 1,
      "startTimestamp": 1792700000000,
      "endTimestamp": 1792703600000,
      "durationMin": 60,
      "subjectName": "阅读",
      "studyContent": "第三章",
      "recordDate": "2026-10-23",
      "createdAt": 1792700000000,
      "updatedAt": 1792703600000
    }
  ],
  "reflections": {}
}
```

**兼容规则**

- 导入时 `app` 接受新名称与旧版「研时记」（`brand.js` 的 `legacyBackupIds`）
- 旧备份缺少时间戳时，用 `recordDate` 推导一个稳定占位值，保证可重复去重
- 导入不强制校验 `formatVersion`，只校验 `app` 与记录基本字段

## 4. 核心业务规则

### 4.1 目标日倒计时

`剩余天数 = (目标日 0 点 − 今天 0 点) / 86400000`，向下取整；当天为 `0 天`，过期显示已过去天数。未设置目标日时首页显示「设定一个目标日」。

### 4.2 计时状态机

```
IDLE ──开始──▶ RUNNING ──暂停──▶ PAUSED
  ▲              │                 │
  └──── 保存/丢弃 ◀───────────────┘
```

- 时长永远由时间戳反算：`elapsed = now − start − pausedMs`
- 暂停累加 `pausedMs`，暂停期间不计时
- 结束：`durationMin = ceil(elapsed / 60000)`
- `record_date` 取**开始日**（跨零点归前一天）
- 每 10 秒把 `{status, startTimestamp, pausedMs, subjectName, mode, targetMinutes}` 写入心跳
- 启动检测到心跳 → 弹「继续 / 丢弃」

**已知缺陷（v1.3 修复）**

- 番茄钟只把数字显示成倒计时，到 0 不会提醒、不会停，记录时长仍是真实 elapsed
- 若 App 被杀后恢复，关机期间按绝对时间计入，可能虚增

### 4.3 统计口径

| 周期 | 区间 |
|---|---|
| 日 | 所选日 0 点 ~ 当天 23:59 |
| 周 | 自然周（周一 ~ 周日） |
| 月 | 自然月 |
| 全部 | 最早记录日 ~ 今天；日均按「有记录的天数」 |

- 累计次数 / 累计时长：全量，不受筛选影响
- 日均：周期总时长 ÷ 已过天数（日视图为 1）
- 科目分布：周期内按 `subject_name` 分组求和，百分比四舍五入

### 4.4 日志排序

**日期倒序 → 同一天内 `created_at` 倒序**。

这样补录的记录一定出现在当天最上面，而不是按虚拟的「开始时间」沉到中间。新增记录会高亮 2.8 秒并提示。

### 4.5 导入合并去重

合并模式用**内容指纹**判重：

```
record_date | subject_name | duration_min | start_timestamp | study_content
```

- 指纹已存在 → 跳过（同一份备份导入两次不会翻倍）
- `record_id` 冲突但内容不同 → 重新分配 id（跨设备导入不丢数据）
- 覆盖模式：先清空，再写入，并恢复备份里的配置

### 4.6 自动备份

- 触发：`records` 变化后 6 秒（去抖）
- 位置：应用私有目录 `backups/snap-YYYYMMDD-HHmmss.json`
- 保留：最近 5 份，超出自动删除
- 恢复：`importBackupJSON(text, 'overwrite')`
- 自愈：启动时若本地无记录且有自动备份 → 提示恢复（用户点「暂不」后写入 `yanshiji_restore_prompted`，不再反复打扰）

> 自动备份只在原生端生效；卸载 App 会一起删除，重要数据必须导出到手机。

## 5. 原生能力

### 5.1 `BackupFilePlugin`

源码：`app/android/app/src/main/java/com/yanshiji/app/BackupFilePlugin.java`
注册：`MainActivity.onCreate` 中 `registerPlugin(BackupFilePlugin.class)`（必须在 `super.onCreate` 之前）。

| 方法 | 参数 | 返回 |
|---|---|---|
| `saveFile` | `{ fileName, data, mimeType }` | `{ uri, name }` 或 `{ cancelled: true }` |
| `openFile` | — | `{ data, uri }` 或 `{ cancelled: true }` |

- 保存走 `ACTION_CREATE_DOCUMENT`，用户自选目录（下载/网盘/本机）
- 打开走 `ACTION_OPEN_DOCUMENT`，MIME 限制 `application/json`、`text/plain`、`application/octet-stream`
- 不需要任何运行时权限
- 取消用 `resolve({cancelled:true})` 而不是 reject，便于前端区分

JS 封装：`src/services/backupFile.js`，Web 端 `isNativePlatform()` 为 false，走 Blob 下载 / `<input type=file>`。

### 5.2 为什么用 SAF，而不是分享

微信接收 `ACTION_SEND` 时只读 `EXTRA_TEXT`，文件流常被忽略，用户收到一段文字。SAF 让文件先落到用户选定的位置，再由微信自己的「＋ → 文件」发送，链路稳定。分享入口仍然保留，但**只放文件流、不放文字**。

## 7. 构建与发布

### 7.1 环境

- Node.js ≥ 20（当前 24）
- **JDK 21**（Capacitor 8 插件要求；本机在 `D:\java21\jdk-21.0.12.1+1`）
- Android SDK 36，build-tools 36.0.0

### 7.2 两条构建命令（base 不同，不能混用）

```bash
# Web 在线版：base=/public/web/，产物 dist/，供 backend 托管
npm run build

# 原生 App：base=/，产物 dist-capacitor/，供 Capacitor 打包
npx vite build --base=/ --outDir=dist-capacitor
```

> 曾经踩过的坑：只跑了 `npm run build` 就 `cap sync`，APK 里仍是旧页面。**打包 APK 必须构建 `dist-capacitor`**。

### 7.3 打包 APK

```bash
npx cap sync android
cd android
./gradlew assembleRelease
```

签名：`android/app/yanshiji-release.keystore` + `android/keystore.properties`（均已 gitignore）。
产物：`app/android/app/build/outputs/apk/release/app-release.apk`。

### 7.4 版本号

- `android/app/build.gradle`：`versionCode` 每次发版 +1，`versionName` 语义化
- `app/package.json`：保持同号
- `src/brand.js`：改名只影响显示，不影响版本

### 7.5 分发

- Gitee / GitHub Releases 上传 APK（`.gitignore` 已排除 `*.apk`）
- 可选：`backend/` 零依赖 Node 分发服务（见 `backend/README.md`）

## 10. 兼容性铁律（改代码前必读）

1. **不要改** `applicationId`（`com.yanshiji.app`）
2. **不要换** 签名密钥（换了必须卸载，数据全失）
3. **不要改** `androidScheme`（`https`，WebView 存储按 origin 隔离）
4. **不要改** localStorage 的 key 与字段名
5. `versionCode` 必须递增
6. 备份导入必须继续接受旧标识「研时记」
7. 升级方式必须是**覆盖安装**，不能卸载
